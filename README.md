# Описание структуры базы данных и архитектуры проекта "Школа фехтования"

## Общая концепция

Данный проект реализует современный сайт для школы фехтования с поддержкой личных кабинетов, онлайн-записи, расписания, галереи, отзывов, новостей, административной панели и гибкой CMS для наполнения страниц.  
База данных построена на PostgreSQL и спроектирована с учетом масштабируемости, безопасности и удобства администрирования.

## Почему так много таблиц?

В проекте реализована сложная и гибкая архитектура, позволяющая:
- Разделять контент на блоки и страницы (CMS-подход).
- Хранить историю заявок, отзывов, расписания, новостей, галерей и т.д.
- Поддерживать мультимедийный контент (изображения, видео).
- Гибко управлять правами пользователей (админ/пользователь).
- Масштабировать проект под разные задачи (например, добавить новые типы страниц или блоков без изменения структуры БД).

Каждая таблица отвечает за отдельную сущность или функциональный модуль, что облегчает сопровождение, расширение и интеграцию с внешними сервисами.

## Описание таблиц

### 1. users — Пользователи сайта

- **id** — уникальный идентификатор пользователя (PK).
- **username** — логин пользователя.
- **password** — хэш пароля (безопасное хранение).
- **is_admin** — флаг администратора (разграничение прав).
- **created_at** — дата регистрации.

**Зачем?**  
Позволяет реализовать регистрацию, авторизацию, разграничение доступа (например, только админ может управлять контентом).

---

### 2. trainers — Тренеры

- **id** — уникальный идентификатор тренера (PK).
- **name** — ФИО тренера.
- **description** — подробная информация, достижения, регалии.
- **image_url** — ссылка на фотографию тренера.
- **created_at** — дата добавления.

**Зачем?**  
Позволяет гибко управлять списком тренеров, выводить их на сайте, связывать с расписанием.

---

### 3. schedule — Расписание тренировок

- **id** — уникальный идентификатор (PK).
- **day** — день недели или дата.
- **time** — время тренировки.
- **trainer_id** — ссылка на тренера (FK).
- **created_at** — дата создания записи.

**Зачем?**  
Позволяет строить динамическое расписание, отображать его на сайте, связывать с тренерами.

---

### 4. applications — Заявки на тренировку/обратную связь

- **id** — уникальный идентификатор (PK).
- **name, phone, email** — контактные данные заявителя.
- **schedule_date, schedule_time** — желаемая дата и время.
- **message** — сообщение пользователя.
- **status** — статус заявки (pending, approved, rejected и т.д.).
- **user_id, user_username** — связь с пользователем (если заявка от зарегистрированного).
- **created_at** — дата создания.

**Зачем?**  
Позволяет реализовать онлайн-запись, хранить историю обращений, отслеживать статус обработки.

---

### 5. reviews — Отзывы

- **id** — уникальный идентификатор (PK).
- **name** — имя автора.
- **text** — текст отзыва.
- **created_at** — дата публикации.

**Зачем?**  
Формирует социальное доказательство, повышает доверие к школе.

---

### 6. gallery — Галерея изображений и видео

- **id** — уникальный идентификатор (PK).
- **title** — название медиа.
- **description** — описание.
- **type** — тип (image, video).
- **url** — ссылка на файл.
- **created_at** — дата добавления.

**Зачем?**  
Позволяет публиковать фото- и видеоматериалы с мероприятий, тренировок, турниров.

---

### 7. blocks — Контентные блоки (CMS)

- **id** — уникальный идентификатор (PK).
- **page_slug** — к какой странице относится блок (например, 'main', 'about').
- **block_type** — тип блока (text, image, gallery, slider, grid и т.д.).
- **title** — заголовок блока.
- **content** — основной контент (HTML, текст, JSON).
- **position** — позиция на странице (для сортировки).
- **visible** — видимость блока.
- **created_at, updated_at** — даты создания и обновления.

**Зачем?**  
Позволяет реализовать гибкую CMS: админ может собирать страницы из блоков, менять их порядок, тип, наполнение без программиста.

---

### 8. main_block_images — Изображения для блоков главной

- **id** — уникальный идентификатор (PK).
- **block_id** — ссылка на блок (FK).
- **url** — ссылка на изображение.
- **alt** — альтернативный текст.
- **created_at** — дата добавления.

**Зачем?**  
Позволяет добавлять к каждому блоку главной страницы свои изображения (например, для слайдера, галереи, сетки).

---

### 9. page_block_images — Изображения для блоков обычных страниц

- **id** — уникальный идентификатор (PK).
- **block_id** — ссылка на блок (FK).
- **url** — ссылка на изображение.
- **alt** — альтернативный текст.
- **created_at** — дата добавления.

**Зачем?**  
Аналогично main_block_images, но для других страниц (например, "О нас", "Контакты" и т.д.).

---

### 10. pages — Обычные страницы (CMS)

- **id** — уникальный идентификатор (PK).
- **slug** — уникальный идентификатор страницы (например, 'about').
- **title** — заголовок страницы.
- **content** — основной контент.
- **updated_at** — дата последнего обновления.

**Зачем?**  
Позволяет создавать и редактировать любые страницы сайта через админку.

---

### 11. posts — Новости/статьи (блог)

- **id** — уникальный идентификатор (PK).
- **title** — заголовок.
- **slug** — уникальный идентификатор (для URL).
- **content** — текст статьи.
- **image_url** — картинка к посту.
- **published** — опубликовано или нет.
- **published_at** — дата публикации.
- **created_at, updated_at** — даты создания и обновления.

**Зачем?**  
Позволяет вести блог, публиковать новости, статьи, анонсы.

---

### 12. session — Сессии пользователей

- **sid** — идентификатор сессии (PK).
- **sess** — данные сессии (JSON).
- **expire** — время истечения.

**Зачем?**  
Для авторизации, хранения состояния пользователя между запросами.

---

## Связи между таблицами

- **main_block_images.block_id → blocks.id** — изображения к блокам главной.
- **page_block_images.block_id → blocks.id** — изображения к блокам других страниц.
- **schedule.trainer_id → trainers.id** — связь расписания с тренером.
- **applications.user_id → users.id** — связь заявки с пользователем (если есть).

## Особенности и преимущества архитектуры

1. **Модульность и масштабируемость**  
   Каждая сущность вынесена в отдельную таблицу, что позволяет легко добавлять новые функции (например, новые типы блоков, страницы, медиа).

2. **Гибкая CMS**  
   Контент сайта собирается из блоков, которые можно менять местами, скрывать, редактировать, добавлять изображения — всё через админку.

3. **Безопасность**  
   Пароли хранятся в виде хэшей, сессии — в отдельной таблице, разграничение прав реализовано через поле is_admin.

4. **Мультимедийность**  
   Поддержка изображений и видео для блоков, галерей, новостей.

5. **История и аудит**  
   Для большинства сущностей ведётся история создания и обновления (created_at, updated_at).

6. **Удобство для пользователя и администратора**  
   Пользователь может записаться на тренировку, оставить отзыв, просмотреть расписание, а админ — управлять всем контентом без программиста.

7. **Поддержка сложных сценариев**  
   Например, можно реализовать расписание с разными тренерами, галереи с видео, страницы с уникальной структурой, блог и т.д.

---

## Почему именно такая структура?

- **Разделение ответственности**: каждая таблица отвечает только за свою сущность.
- **Гибкость**: можно быстро менять структуру страниц, не трогая код.
- **Масштабируемость**: легко добавить новые типы блоков, страниц, медиа, пользователей.
- **Безопасность и аудит**: все действия фиксируются, есть разграничение прав.
- **Удобство поддержки**: админка позволяет управлять всем контентом без программиста.

---

## Пример пользовательских сценариев

- **Пользователь**: Регистрируется, записывается на тренировку, оставляет отзыв, просматривает расписание, читает новости, смотрит галерею.
- **Администратор**: Добавляет/редактирует тренеров, управляет расписанием, модерирует заявки, наполняет страницы контентом, публикует новости, управляет галереей.

---

## Заключение

Данная структура БД и архитектура проекта позволяют реализовать современный, гибкий, масштабируемый и безопасный сайт для спортивной школы с возможностью дальнейшего расширения и интеграции с внешними сервисами.

Если потребуется добавить новые функции (например, онлайн-оплату, рассылки, интеграцию с соцсетями) — это можно сделать без глобальных изменений в существующей структуре.
